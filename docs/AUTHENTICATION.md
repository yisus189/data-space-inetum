# Authentication and Observability (Fase 4)

This document describes the authentication, error handling, and monitoring features implemented in Fase 4.

## JWKS Cache and Token Verification

### Overview
The application now supports JWT token verification using Keycloak's JWKS (JSON Web Key Set) endpoint with intelligent caching.

### Configuration
Set the following environment variables in your `.env` file:

```bash
# OIDC/Keycloak settings
OIDC_ISSUER=http://keycloak:8080/realms/dataspace
OIDC_AUDIENCE=dataspace-api
OIDC_JWKS_URI=http://keycloak:8080/realms/dataspace/protocol/openid-connect/certs  # Optional, auto-discovered if not set
OIDC_JWKS_TTL=3600  # Cache TTL in seconds (default: 1 hour)

# Monitoring
SENTRY_DSN=your-sentry-dsn  # Optional
PROMETHEUS_ENABLED=true  # Enable/disable metrics endpoint
```

### Features

#### 1. JWKS Caching
- **TTL-based cache**: JWKS is cached for the configured TTL (default 1 hour)
- **Conditional requests**: Uses ETag/Last-Modified headers to avoid unnecessary downloads
- **Automatic refresh**: On unknown `kid` in token, JWKS is refreshed and verification retried
- **Exponential backoff**: Network errors trigger retries with exponential backoff (3 attempts)

#### 2. Token Verification
The `verify_and_decode()` function validates:
- **Signature**: Using public keys from JWKS
- **Claims**:
  - `iss` (issuer): Must match configured issuer
  - `aud` (audience): Must match configured audience
  - `exp` (expiration): Token must not be expired
  - `nbf` (not before): Token must be valid

#### 3. Error Responses
Clear error messages for different failure scenarios:
- **401 Unauthorized**: Invalid token, expired token, immature signature
- **403 Forbidden**: Wrong audience, untrusted issuer
- **503 Service Unavailable**: Unable to fetch JWKS

### Usage Example

```python
from src.auth.keycloak import verify_and_decode

# Verify a JWT token
try:
    payload = verify_and_decode(token)
    user_id = payload['sub']
    # Token is valid, proceed with request
except HTTPException as e:
    # Handle authentication error
    print(f"Auth failed: {e.detail}")
```

## Error Handling Middleware

### Structured Error Responses
All errors are returned in a consistent JSON format:

```json
{
  "error": {
    "code": "error_code",
    "message": "Human-readable error message",
    "request_id": "unique-request-id",
    "details": {}  // Optional additional details
  }
}
```

### Request ID Tracking
Every request gets a unique request ID:
- Generated by the error middleware
- Included in all error responses
- Added to response headers as `X-Request-ID`
- Logged with all error messages

### Error Types
- **HTTP errors** (404, 401, etc.): Code = `http_{status_code}`
- **Validation errors**: Code = `validation_error` with details
- **Internal errors**: Code = `internal_server_error`

## Prometheus Metrics

### Metrics Endpoint
Access metrics at: `GET /metrics`

### Available Metrics

#### HTTP Metrics
- `http_requests_total`: Total HTTP requests by method, endpoint, and status
- `http_request_duration_seconds`: Request duration histogram by method and endpoint

#### Authentication Metrics
- `jwks_cache_hits_total`: Number of JWKS cache hits
- `jwks_cache_misses_total`: Number of JWKS cache misses
- `token_verifications_total`: Total token verifications by status (success/failure)

### Usage with Prometheus
Configure Prometheus to scrape the metrics endpoint:

```yaml
scrape_configs:
  - job_name: 'dataspace-api'
    static_configs:
      - targets: ['localhost:8000']
    metrics_path: '/metrics'
```

## Security Considerations

1. **JWKS caching**: Reduces load on Keycloak but may delay key rotation. Adjust TTL based on your key rotation policy.
2. **Request IDs**: Enable correlation of errors across distributed systems.
3. **Error messages**: Provide enough information for debugging without leaking sensitive data.
4. **Metrics**: Monitor authentication failures to detect potential attacks.

## Logging

The application logs:
- JWKS cache hits/misses
- Token verification successes/failures
- All HTTP errors with request IDs
- Unhandled exceptions with full stack traces

Configure logging level via environment variable:
